# Timing manipulation in After Effects: shift, offset, stagger, sequence, overlap and retime (native, expressions, scripts/plugins)

Research date: 2026-10-09. Scope: how AE users move keyframes and layers in time, and what each technique implies for a native feature in an AE-class motion app. Note on sourcing: direct fetches of helpx.adobe.com, aescripts.com, mtmograph.com, gumroad.com, motiondesign.school, frame.io and aejuice.com were blocked by the research proxy, so facts from those pages come from search-engine extracts of them plus Adobe Community / Creative COW / aescripts forum threads. Prices and version numbers should be re-verified on the vendor pages before publication.

## Key Question 1: Native AE features and hidden shortcuts for shifting, staggering, sequencing and retiming

### Takeaway
AE's native timing toolkit is a patchwork: one keyframe assistant that sequences whole layers (Sequence Layers), one modifier-drag that scales keyframe groups (Alt-drag, which leaves sub-frame keys), one modifier-drag added only in August 2025 that staggers layers or per-layer keyframe groups (Quick Offset, Ctrl/Cmd+Alt/Opt-drag), nudge shortcuts (Alt+arrow = 1 frame, Alt+Shift+arrow = 10 frames), Shift-drag snapping, Time Stretch / Time Remap / Time-Reverse Keyframes for retiming, and J/K (23.0: Shift+J/K) navigation. None of it offers a typed per-item offset, intra-layer keyframe staggering, random/eased distribution, or a view of relative timing across layers, which is exactly what the plugin market fills.

### Cited Findings

**Sequence Layers keyframe assistant (Animation > Keyframe Assistant > Sequence Layers)**
- Workflow: add layers to a comp, trim them as needed (they do not need equal length), select them, apply Animation > Keyframe Assistant > Sequence Layers; the dialog has an Overlap checkbox, a Duration field and a Transition popup — [ProVideo Coalition, After Effects Hidden Gems: Sequence Layers](https://www.provideocoalition.com/after-effects-hidden-gems-sequence-layers/)
- "First, the Overlap option must be enabled. If Duration is set to a positive amount of time, the layers will be overlapped by the set Duration as they are sequenced in time"; the Duration field has no effect unless Overlap is checked — [ProVideo Coalition](https://www.provideocoalition.com/after-effects-hidden-gems-sequence-layers/)
- Setting Duration to a negative time creates gaps between layers instead of overlaps — [ProVideo Coalition](https://www.provideocoalition.com/after-effects-hidden-gems-sequence-layers/)
- Transition options: "Off" adds no opacity keyframes; "Dissolve Front Layer" keeps the underlying layer at 100% opacity and fades the top layer in/out (best for full-frame layers or matching alpha); "Cross Dissolve Front and Back Layers" fades one up while the other fades out (best for text/logos without matching alpha; has an opacity dip in the middle) — [ProVideo Coalition](https://www.provideocoalition.com/after-effects-hidden-gems-sequence-layers/)
- Stagger recipe: trim the selected layers to the playhead with Alt/Opt+] (or drag layer handles), right-click a selected layer > Keyframe Assistant > Sequence Layers, leave Overlap unchecked so each layer begins where the previous one ends — [Frame.io blog, Insider tips: staggered layer sequence](https://blog.frame.io/2023/12/13/insider-tips-how-to-create-a-staggered-layer-sequence-in-after-effects); [AEJuice, How to stagger layers](https://aejuice.com/blog/how-to-stagger-layers-in-after-effects)
- Overlap is literal overlap of layer bars, not an offset: a 10-frame overlap on 30-frame layers yields a 20-frame offset between starts, not a 10-frame offset — [LinkedIn Learning / Lynda, AE CC 2018 Editors and Post](https://www.lynda.com/After-Effects-tutorials/Move-animated-images-around-frame/625926/678825-4.html)
- Order is the selection order: "the order that you select layers affects the order of the final sequence. Your sequence is going to start at the beginning of the first layer you select"; Ctrl/Cmd-click to add layers in any order — [Lynda, After Effects Apprentice: Layer Control](https://www.lynda.com/After-Effects-tutorials/Understanding-importance-layer-order/79655/80668-4.html?src=c.r.su); to sequence bottom-up "start at the bottom, hold down the shift key, then click the top" — [Adobe Community, Sequence Layers command troubles](https://community.adobe.com/t5/after-effects-discussions/sequence-layers-command-troubles/m-p/11824481)
- A beta build (22.2.0x105) was reported to always sequence top-to-bottom regardless of selection order; no fix confirmation found — [Adobe Community beta bugs](https://community.adobe.com/t5/after-effects-beta-bugs/animation-gt-sequence-layers-doesn-t-respect-selection-order/idc-p/12787371)
- Common failure: sequenced layers run past the comp end because "Sequence Layers uses the full layer duration to align the layers in time"; trimming with Alt/Opt+[ or ] rather than dragging out-points avoids it — [Adobe Community (Adobe engineer reply)](https://community.adobe.com/t5/after-effects-discussions/keyframe-assistant-sequence-layers-n%C3%A3o-est%C3%A1-fazendo-a-sequ%C3%AAncia-de-todas-as-camadas-selecionadas/m-p/14592761)

**Quick Offset (AE 25.4, August 2025) — Ctrl+Alt-drag (Win) / Cmd+Opt-drag (Mac)**
- "Hold Command + Option on macOS or Ctrl + Alt on Windows, then drag your layers to create staggered layer or keyframe animations in the Timeline panel" — [Adobe, After Effects feature summary (August 2025 / 25.4)](https://helpx.adobe.com/after-effects/using/whats-new/2025-4.html)
- Behaviour: "The first layer you selected stays in place, while the last layer moves the full distance you drag. All layers in between are evenly spaced in time between the first and last" — [Adobe 25.4 feature summary](https://helpx.adobe.com/after-effects/using/whats-new/2025-4.html)
- Keyframes: "select keyframes across multiple layers, then hold the keyboard shortcut and drag to stagger their timing across layers"; groups of keyframes on each layer stay together — [Adobe 25.4 feature summary](https://helpx.adobe.com/after-effects/using/whats-new/2025-4.html)
- On-screen overlay during the drag: "'Total Offset' shows the full duration or frame count across all selected layers, while 'Per Layer' indicates the time gap between each individual layer" — [Adobe 25.4 feature summary](https://helpx.adobe.com/after-effects/using/whats-new/2025-4.html); also [RedShark News, Adobe introduces After Effects 25.4](https://www.redsharknews.com/adobe-introduces-after-effects-25.4)
- Introduced in Beta 25.4 build 50, then shipped in release 25.4; layers distribute "in the order you selected them"; Adobe's suggested combo is Alt/Opt-drag to duplicate layers in the comp viewer, then Quick Offset to cascade them — [Adobe Community, Feature Focus: Quick Offset](https://community.adobe.com/t5/after-effects-beta-discussions/feature-focus-quick-offset-stagger-your-layers-just-by-dragging-them/m-p/15377310)
- Known limit (Adobe employee, Sept 2025): "Quick Offset only works across multiple layers and it considered each layer a unit... when selecting keyframes across multiple layers, all keyframes on the same layer move together" — intra-layer keyframe staggering was logged as a feature request — [Adobe Community thread, later page](https://community.adobe.com/t5/after-effects-beta-discussions/feature-focus-quick-offset-stagger-your-layers-just-by-dragging-them/m-p/15566526/highlight/true); a related bug report "stagger isn't behave like expected" exists — [Adobe Community bugs](https://community.adobe.com/t5/after-effects-bugs/stagger-isn-t-behave-like-expected/idc-p/15484699)

**Alt/Option-drag to scale a keyframe group proportionally**
- "Select the keyframes and hold down Alt/Option as you drag the outer one, the first keyframe in the selected group stays in position, the middle ones move proportionally" — [Adobe Community, keyframes proportional to comp length](https://community.adobe.com/t5/after-effects-discussions/how-to-make-keyframes-proportionally-to-the-composition-length-in-after-effects/m-p/14384044/highlight/true)
- "Always select the edge-most keyframe to select+ALT/Option+drag" — grabbing a non-edge key moves the group instead of stretching it, which users report as inconsistent behaviour — [Adobe Community, trying to stretch keyframes](https://community.adobe.com/questions-529/trying-to-stretch-keyframes-to-be-longer-and-in-proportion-60789)
- Sub-frame side effect: "Time stretching with the Alt/Opt key is a great way to quickly adjust the length of an animation, but it almost always leads to subframe positioning of keyframes"; users request a modifier (e.g. Shift+Alt) to quantize to whole frames — [Adobe Community idea: Option to quantize keyframes when time stretching with Alt key](https://community.adobe.com:443/t5/after-effects-ideas/option-to-quantize-keyframes-when-time-stretching-with-alt-key/idc-p/14067207); separate request "snap to nearest frame when scaling keyframes along timeline" — [Adobe feature request](https://community.adobe.com/feature-requests-530/feature-request-snap-to-nearest-frame-when-scaling-keyframes-along-timeline-1215196)
- Workarounds for sub-frame keys: the KEYboard script has an "align to nearest frame" feature ("After certain manipulations (notably stretch), keyframes can end up between two frames") — [aescripts forum](https://aescripts.com/forums/discussion/comment/50702/); a free asu_NudgeKeyFrames.jsx by Anders Sundstedt is cited as a temporary fix; one hack for moving a key by 1/10-frame increments is to add temporary keys 1 frame before and 10 frames after, select all three and Alt-drag the last — surfaced in Creative COW threads ([Creative COW](https://creativecow.net/?p=171442); exact thread among several returned by search not verified)
- Alternatives: roving keyframes (position-type properties only) re-space proportionally when outer keys move; the Graph Editor's free-transform box lets you "scale, move, taper" a selection — [Creative COW, scaling keyframe distance like Maya](https://creativecow.net/forums/thread/scaling-keyframe-distancelike-in-maya/)

**Shift-drag snapping**
- "hold down the shift key when dragging keyframes and they will snap to any other visible keyframe or marker's time" (Adobe Community Expert) — [Adobe Community, CTI jump between keyframes](https://community.adobe.com/t5/after-effects-discussions/how-to-make-the-current-time-indicator-jump-between-keyframes/td-p/14577510)

**Keyframe navigation (J/K; Shift+J/K added in 23.0)**

**Time Stretch, Time-Reverse, Time Remap**
- Time Stretch applies one constant factor to a whole layer: "the audio and the original frames in the footage (and all keyframes that belong to the layer) are redistributed along the new duration"; dialog fields are New Duration and Stretch Factor (%), which stay linked, plus Hold In Place (Layer In-point default, Current Frame, Layer Out-point) — [Adobe Help, Time-stretching and time-remapping](https://helpx.adobe.com/ca/after-effects/desktop/animate-in-after-effects/time-stretching-and-time-remapping/time-stretching-time-remapping.html); [ProVideo Coalition, CMG Hidden Gems ch. 28 frame rate manipulation](https://www.provideocoalition.com/cmg_hidden_gems_chapter_28_frame_rate_manipulation/)

- Animation > Keyframe Assistant > Time-Reverse Keyframes reverses a selected range in place: each property's keys reverse only within their own original span; markers do not move — [Adobe Help](https://helpx.adobe.com/ca/after-effects/desktop/animate-in-after-effects/time-stretching-and-time-remapping/time-stretching-time-remapping.html)

**Markers and misc native tools**
- Markers are the main native reference for timing but Time-Reverse Keyframes leaves them in place — [Adobe Help](https://helpx.adobe.com/ca/after-effects/desktop/animate-in-after-effects/time-stretching-and-time-remapping/time-stretching-time-remapping.html); Paul Tuersley's pt_LayerMarkers script exists to batch-manipulate markers — [aescripts pt_layermarkers](https://aescripts.com/pt_layermarkers/)
- Randomising keyframe *timing* has no native command: a request for "jitter keyframe timing" noted wiggle handles values, "there was no equivalent for time" — [Adobe Community](https://community.adobe.com/t5/after-effects-discussions/jitter-keyframe-timing/m-p/10532799)

### Inferences
- Native equivalents implied: (1) a Sequence/Stagger command whose offset is defined as start-to-start spacing (users are repeatedly bitten by "overlap" being bar overlap, not offset), with explicit order control (selection, stacking, reverse, random) rather than relying on click order; (2) scaling a selection in time must either quantize to frames by default or expose a "snap to frames" toggle, because AE's Alt-drag is the number-one source of sub-frame keys; (3) Quick Offset's drag-with-overlay (Total / Per Item) is the UX benchmark Adobe itself chose in 2025, but a native tool should work within one layer and accept typed values; (4) nudges (1 and 10 frames) and Shift-snapping to keys/markers/playhead are table stakes; (5) selected-only navigation (Shift+J/K) should be the default behaviour with "all layers" as the option.
- The Properties panel has not added timing tools; it reduces twirl-time but offsets, staggers and retimes are still timeline-only gestures.

## Key Question 2: Expression tricks for delay, offset, follow and retime, and how they get baked

### Takeaway
The canonical delay is `master.property.valueAtTime(time - delay)`, scaled by `index` so a layer stack staggers itself; slider controls on a null make the delay editable, `thisComp.layer(index-1)` chains create follow-through but get slow past ~4 links, `loopOut("offset")` is value-accumulating (not a time offset), `linear()`/`ease()` remap time ranges, and Convert Expression to Keyframes bakes one key per frame with known failures (expression selectors, wiggle on paths, very complex expressions).

### Cited Findings
- Basic delay on a follower: `thisComp.layer("word 1").opacity.valueAtTime(time - 0.5)`, with later words at 1.0 s and 1.5 s — tedious to maintain by hand — [Motion Array, How to offset layers](https://blog.motionarray.com/learn/after-effects/how-to-offset-layers-in-after-effects/)
- Index-driven stagger with a slider: `m = index - 4; d = thisComp.layer("Controller").effect("Delay")("Slider"); thisComp.layer("Text Box 1").transform.position.valueAtTime(time - d*m);` — the hard-coded 4 breaks if a layer is inserted above — [Motion Array](https://blog.motionarray.com/learn/after-effects/how-to-offset-layers-in-after-effects/); robust form `m = index - thisComp.layer("Text Box 1").index;` — [Adobe Community, offset layers in position as well as time](https://community.adobe.com/t5/after-effects-discussions/expression-to-offset-layers-in-position-as-well-as-time/m-p/13908763)
- Frame-based variant: `delay = 15; d = delay*thisComp.frameDuration*(index - 1); thisComp.layer("targetLayer").rotation.valueAtTime(time - d)` — [AEJuice, Delay expression](https://aejuice.com/blog/delay-expression-in-after-effects)
- Daisy chain: `thisComp.layer(index-1).transform.position.valueAtTime(time-delay);` with the leader holding the keyframes — [Adobe Community, expression with delay](https://community.adobe.com/t5/after-effects-discussions/expression-with-delay/m-p/4438312); the offset compounds down the stack (e.g. each layer starts 10 frames after the one below) — [Adobe Community, time-delayed movement in one axis](https://community.adobe.com/t5/after-effects/how-to-create-a-time-delayed-movement-in-one-axis-only/m-p/11774615)
- Performance: "once you get past about four or so of these references, you should give serious thought to using absolute indexing" (`thisComp.layer(1)...valueAtTime(time - (index-1)*0.5)`), which requires disciplined layer stacking — [ProVideo Coalition, Deeper Modes of Expression 6: time](https://www.provideocoalition.com/dmoe6_time/)
- Advanced valueAtTime delay rigs (Shinsuke Matsumoto) and School of Motion's "fake the C4D MoGraph module" use the same primitive — [Lester Banks](https://lesterbanks.com/?p=49769); [School of Motion tutorial](https://www.schoolofmotion.com/tutorials/faking-c4d-mograph-module-after-effects); overview of `time`-based expressions — [School of Motion, time expression](https://schoolofmotion.com/blog/time-expression-after-effects)
- `loopOut()` types: "cycle" (default) repeats keys; "pingpong" alternates direction; "offset" repeats while adding the cumulative change each loop (0-30° rotation keeps climbing); "continue" extrapolates the last velocity; a second argument limits how many keys loop (`loopOut("pingpong", 1)`); first and last keys must match for seamless cycles; offset/continue have no visible effect on a 0-100 trim path — [School of Motion, loop expression](https://www.schoolofmotion.com/blog/loop-expression-after-effects); [Made by Loop, loopOut reference](https://madebyloop.co.uk/after-effects-expressions/loopOut/); [Adobe Community, looping tips](https://community.adobe.com/t5/after-effects-discussions/tips-amp-tricks-for-looping-keyframes-with-expressions-in-after-effects/m-p/11266450/highlight/true)
- `linear()` / `ease()` time remaps: signature `ease(t, tMin, tMax, value1, value2)`; slider-driven start/duration, e.g. `fadeTime = thisComp.layer(1).effect("Fade Time")("Slider")/frames; ease(time - startTime, 0, fadeTime, 0, 100)`, with a guard `if (time <= start)` to hold the pre-start value; `linear()` is more predictable than `ease()` when mapping ranges — [Adobe Community, time control expression with slider for MOGRT](https://community.adobe.com/t5/after-effects-discussions/time-control-expression-of-layer-with-slider-for-use-with-a-mogrt/m-p/11452252/highlight/true); [Adobe Community, custom ease](https://community.adobe.com/t5/after-effects-discussions/custom-ease-easing/td-p/10594573)
- Baking: select layer, press EE to show expressions, select the property, Animation > Keyframe Assistant > Convert Expression to Keyframes — [Webflow forum, Lottie/AE wiggle thread](https://discourse.webflow.com/t/lottie-ae-wiggle-effect-bodymovin-oh-my/100067)
- Baking limits: it does not work the normal way for expressions on text-animator expression selectors (Dan Ebberts) — [Creative COW](https://creativecow.net/?p=1851999); produces a key on every frame so it does not speed renders — [Creative COW](https://creativecow.net/?p=1840767); wiggle on paths cannot be converted directly (precompose + auto-trace workaround is slow) — [Adobe Community](https://community.adobe.com/t5/after-effects-discussions/can-you-convert-wiggle-paths-to-keyframes/m-p/12642974/highlight/true); Lottie users bake because unsupported expressions do not export — [Adobe Community](https://community.adobe.com/questions-529/need-help-with-my-json-format-animation-46642); third-party Easy Bake bakes whole comps/layers and prunes redundant keys — [Lester Banks, Easy Bake](https://lesterbanks.com/?p=41621); the Hidden Gems expressions chapter covers the same assistant — [ProVideo Coalition](https://www.provideocoalition.com/cmg_hidden_gems_chapter_37_expressions/)

### Inferences
- Users write these expressions because AE has no non-destructive "time offset" attribute on a layer or property. A native per-layer/per-property Time Offset parameter (like Cinema 4D's Animation tag or Apple Motion's Start Offset, both found in the search results) would replace `valueAtTime(time - d)`, the index arithmetic and the slider rig in one control, and would stay editable after the fact.
- A native "follow" (driver → follower with delay) replaces `thisComp.layer(index-1)` chains without the chained-evaluation performance cliff.
- Baking should be a lossless, optional step with keyframe reduction, not one-key-per-frame.

### Gaps
- No source directly documents how `valueAtTime(time - delay)` behaves before a layer's in-point or beyond its out-point (clamping vs extrapolation) — treat as unverified.
- Could not fetch the Motion Array / AEJuice pages in full; code above is as extracted by search.

## Key Question 3: Scripts and plugins (controls, invocation, price, praise/complaints)

### Takeaway
The market splits into (a) one-shot shift/stagger panels for layers and keyframes — Rift (NYOP, ~$29.99 suggested), Dojo Shifter v2 (Gumroad, $0+), pt_ShiftLayers ($9.99 suggested), Staircase, Stratify ($19.99), Keystone 2, TimeOffset, Mister Horse Transition Shifter (free with Animation Composer) — (b) suites with a Stagger page plus expression-based delay rigs — Mt. ### Inferences
- The plugin controls converge on one data model: a selection (layers and/or keyframes, optionally grouped), an ordering (selection, stack, reverse, label, spatial pattern, random with seed), a spacing (interval start-to-start, overlap, or distribute across a duration/work area), an easing of the spacing (linear/in/out/both with strength), and a relative-vs-absolute toggle anchored to the playhead. A native tool exposing exactly those five parameters in one popover would cover Rift, Dojo Shifter, Staircase, Stratify, pt_ShiftLayers, Keystone and Motion Stagger.
- Two features the one-shot scripts cannot do and users want: non-cumulative-vs-cumulative stagger (Keystone complaint) argues for a live, scrubbable parameter rather than a fire-and-forget button; Rift's per-layer-only keyframe shifting argues for keyframe-level selection inside one layer.
- Delay rigs (Mt. Mograph Delay, Overlap, Layer Repeater) prove demand for a non-destructive follower/offset system; a native "time offset" attribute and a "follow layer X with delay" link would make them unnecessary.

## Key Question 4: What "overlapping" and "offsetting" mean in tutorials, and the typical offsets

### Takeaway
In AE tutorials "overlap/offset" means starting one property's (or one layer's) keyframe pair a few frames after another's so motions cascade instead of moving in lock-step; the accessible written sources recommend copying a driver's keys to followers and shifting each by a few frames (2–4 is the commonly cited starting point), with scripts (Overlap) or expressions when the layer count makes hand-offsetting tedious.

### Cited Findings
- School of Motion frames follow-through/overlapping action as a principle that "can add loads of visual interest and realism" and notes the technique does not require artwork split into layers — [School of Motion, Animation tricks: follow-through in AE](https://www.schoolofmotion.com/blog/animation-tricks-follow-through-after-effects)
- Overlapping action is defined as "the delayed timing between parts moving together during the main action", distinct from follow-through, which happens after the main motion — [Pixune, Follow-through and overlapping action](https://pixune.com/blog/follow-through-and-overlapping-action/); drag = parts trailing the main action due to weight/inertia, "each joint moves with a slight delay compared to the previous one, creating a cascading effect" — [RebusFarm blog](https://rebusfarm.net/blog/follow-through-and-overlapping-action-the-animation-principle-that-prevents-stiff-motion)
- Practical AE recipe: set the second object's keyframes slightly after the first's, "two at a time, because they are two separate objects" — [Bring Your Own Laptop, offset two objects](https://www.bringyourownlaptop.com/courses/Animated-Infographic-aVideo-and-Data-Visualisation/animating-tip-off-set-two-objects-moving-just-after-each-other-in-after-effects); a 2026 AE fundamentals course has a dedicated "mastering overlapping" lesson — [Elephorm, AE 2026 overlapping](https://www.elephorm.com/formation/apprendre-after-effects-2026-les-fondamentaux/maitriser-loverlapping-en-animation-sur-after-effects-2026)
- Manual keyframing "becomes tedious when you need to make mass edits to many, many layers. Each layer with its own set of keyframes" — the stated reason for the Overlap script — [Lester Banks, Overlap](https://lesterbanks.com/?p=35455); same motivation for expressions: "creating an offset using keyframes might become problematic when working with many layers" — [Motion Array](https://blog.motionarray.com/learn/after-effects/how-to-offset-layers-in-after-effects/)
- Animation Mentor (Anthony Wong): overlap "comes from timing offsets, but always in relation to a well animated base"; copy, paste and offset curves, then polish — [Animation Mentor blog](https://www.animationmentor.com/?p=96605)
- Ben Marriott's Adobe MAX 2022 session covers "using overlapping action to make elements feel alive" and breaking complex animation into repeatable elements — [Adobe MAX 2022 session S907](https://www.adobe.com/max/2022/sessions/apac-behind-the-magic-engaging-animation-and-motio-s907.html)
- Jake Bartlett (Jake in Motion) on retiming many staggered keys: keep keys linear, precompose, time-remap to ease them all together — [Reddit via redlib](https://redlib.hackliberty.org/r/MotionDesign/comments/1hktal5/how_do_i_make_this_or_similar)
- Hand stagger of duplicated layers: Ctrl+D the animated layer, move the copies' keyframes, then precompose to manage them — [AEJuice, How to stagger layers](https://aejuice.com/blog/how-to-stagger-layers-in-after-effects)
- "10 days, 10 teachers" follow-through tip and a LinkedIn Learning lesson on continuous motion/overlapping action exist as further AE-specific references — [LifeArt design blog](https://lifeart.design.blog/2020/06/28/design-motion-10days-follow-through); [Lynda, Continuous motion, overlapping action](https://www.lynda.com/After-Effects-tutorials/Continuous-motion-overlapping-action-Wiggle/570968/628466-4.html)

### Inferences
- The pedagogy is "same curve, shifted in time" — which is why copy/paste + nudge, Sequence Layers, Quick Offset and `valueAtTime` all serve the same goal. A native "offset by N frames per selected item (per property or per layer)" with live preview is the direct equivalent.
- The "one property ends before the next starts" pitfall (hard cuts between motions) is addressed by tutorials via overlap of key ranges, so a native stagger tool should default to overlapping ranges rather than butting them end-to-end (the opposite of Sequence Layers' default).

### Gaps
- I could not retrieve the bodies of the School of Motion, Jake in Motion, Ben Marriott, ECAbrams or Ukramedia tutorials, so specific recommended frame counts or percentages from those creators are unconfirmed; the "2–4 frames" starting point comes from search summaries of general animation guidance, not a named AE expert.
- No ECAbrams or Ukramedia material on offsets surfaced at all.

## Key Question 5: How users view relative timing across properties/layers, and what they say is missing

### Takeaway
AE offers only two keyframe views — layer-bar mode (diamonds aligned with layer bars, exposed via U/UU) and the Graph Editor (curves, no layer bars) — and users ask for a dope-sheet-style timing view, numeric scaling, keyframe guides, snapping to frames, and ways to move keys on one layer together with another layer without disturbing it.

### Cited Findings
- Adobe: "Layer bar mode is the default, which shows layers as duration bars, with keyframes and expressions aligned vertically with their properties in the Timeline panel. Graph Editor mode does not show layer bars, and shows keyframes and expression results in value graphs or speed graphs" — [Adobe Help, Animation basics](https://helpx.adobe.com/in_hi/after-effects/desktop/animate-in-after-effects/animation-basics/animation-basics.html)
- Open feature request (June 2026): an animation Dope Sheet for "blocking, retiming, spacing, and coordinating many layers and properties at once... seeing which layers hit on the same frame and where holds and overshoots fall"; today this "often requires manually expanding and collapsing properties, selecting many separate keyframes, using markers, shifting layer bars, or jumping between views" — [Adobe Community feature request](https://community.adobe.com/feature-requests-530/an-animation-dope-sheet-in-after-effects-1629664)
- Request for "keyframe guides" (vertical guides to line keys up across layers) — [Adobe Community](https://community.adobe.com/t5/after-effects-discussions/feature-request-keyframe-guide/m-p/11892650)
- Request to "move layer and selected keyframes on a second layer without moving the second layer" (currently solved with Nudge + KBar) — [Adobe feature request](https://community.adobe.com/feature-requests-530/move-layer-and-selected-keyframes-on-a-second-layer-without-moving-the-second-layer-1214789)
- Graph Editor pain: multiple selected properties produce stuck/confusing graphs; selecting keys in the timeline does not always carry into the Graph Editor — [Adobe Community, graph editor stuck with multiple keyframes](https://community.adobe.com/t5/after-effects-discussions/graph-editor-stuck-with-multiple-keyframes/td-p/11895162); [Adobe Community, selection not going to graph editor](https://community.adobe.com/t5/after-effects-discussions/after-effects-selected-keyframes-selection-not-going-to-graph-editor/m-p/10764725/highlight/true)
- Scaling a selection is imprecise and un-typeable; users want a scale percentage in the info pane — [Adobe idea, scale keyframes precisely](https://community.adobe.com/t5/idea-after-effects/graph-editor-improvements-|-scale-keyframes-precisely/idi-p/15283237); sub-frame keys after scaling need a quantize option — [Adobe idea](https://community.adobe.com:443/t5/after-effects-ideas/option-to-quantize-keyframes-when-time-stretching-with-alt-key/idc-p/14067207)
- Select-all-keyframes only covers visible keys, so hidden properties are silently excluded from bulk moves — [Adobe Community](https://community.adobe.com/t5/after-effects/select-all-keyframes-in-a-composition/m-p/9686516)
- Time-randomisation has no native equivalent to `wiggle` — [Adobe Community, jitter keyframe timing](https://community.adobe.com/t5/after-effects-discussions/jitter-keyframe-timing/m-p/10532799)
- Sequence Layers order confusion recurs because order is implicit in click order — [Adobe Community](https://community.adobe.com/t5/after-effects-discussions/sequence-layers-command-troubles/m-p/11824481)

### Inferences
- A native app should ship a multi-layer dope-sheet/timing view (all keyed properties across selected layers on one strip, with alignment guides and a "same frame" highlight), numeric time-scaling with frame quantisation, and bulk operations that act on all keys of a selection whether or not the property rows are expanded.
- Random time jitter (with seed) and ordered distribution (ascending/descending/random/by-label/by-position) belong in the same native stagger control, because every plugin adds them.
